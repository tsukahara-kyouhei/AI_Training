# 改善要望・変更管理

## 概要

改善要望・機能追加・仕様変更の要件定義を管理するフォルダ。
要望1件につき1ディレクトリを作成し、関連ドキュメントを格納する。

---

## ディレクトリ命名規則

```
YYYYMMDD_[要望を表す短い名称（英字ケバブケース）]/
```

**例**
```
20260325_product-search-enhancement/
20260401_member-bulk-import/
20260510_admin-dashboard/
```

- `YYYYMMDD`: 要望が起票された日付
- 名称は内容が一目でわかる簡潔な英語表記とする
- 複数単語はハイフン（`-`）でつなぐ

---

## 各ディレクトリの構成

| ファイル | 説明 | 必須 |
|---|---|---|
| `01_overview.md` | 要望の概要（背景・目的・対象範囲） | ✓ |
| `02_requirements.md` | 要件定義書（機能要件・非機能要件） | ✓ |
| `03_questions.md` | 要件確認事項一覧（未決事項・回答） | ✓ |
| `04_design-changes.md` | 設計検討（修正・追加するドキュメントの一覧と変更内容） | ✓（要件確定後） |
| `05_development-plan.md` | 開発計画（修正・追加するモジュールの一覧と変更内容） | ✓（設計完了後） |
| `06_test-plan.md` | テスト計画・テストケース | 任意 |

ひな型は [`_template/`](./_template/) を参照すること。

---

## ステータス管理

各 `01_overview.md` のヘッダに以下のステータスを記載する。

| ステータス | 意味 |
|---|---|
| `📋 要件確認中` | 要件確認事項の回答待ち |
| `📝 要件定義中` | 要件定義書を作成中 |
| `✅ 要件確定` | 要件が確定し設計検討可能な状態 |
| `📐 設計検討中` | 設計変更のドキュメント一覧を作成中 |
| `📐 設計確定` | 設計変更の内容が確定し開発計画を策定可能な状態 |
| `📦 開発計画中` | モジュール単位の修正・追加計画を作成中 |
| `🚧 実装中` | 開発計画に基づき実装作業中 |
| `✔️ 完了` | リリース済み |
| `❌ 却下` | 要望が却下または保留 |

---

## ワークフロー

```
1. 📋 要件確認中    要望受領 → 確認事項の洗い出し・回答収集
                    成果物: 01_overview.md, 02_requirements.md, 03_questions.md

2. 📝 要件定義中    回答をもとに要件定義書を更新
                    成果物: 02_requirements.md（版数更新）

3. ✅ 要件確定      確認事項がすべて解決し要件が確定

4. 📐 設計検討中    どのドキュメントをどのように修正・追加するかを整理
                    成果物: 04_design-changes.md

5. 📐 設計確定      設計変更内容の確定

6. 📦 開発計画中    どのモジュールにどのような修正・追加を行うかを整理
                    成果物: 05_development-plan.md

7. 🚧 実装中        開発計画に基づき実装・テスト実施
                    成果物: 06_test-plan.md（任意）

8. ✔️ 完了          リリース完了
```
