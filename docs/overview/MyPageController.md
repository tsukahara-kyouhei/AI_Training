## 1. 機能概要

- ログイン済み会員が注文履歴や注文内容を確認し、過去に購入した商品をカートへ再度追加できる。
- お気に入り商品を一覧で確認できる。
- 登録済みの会員情報を変更できる。
- 追加のお届け先を登録・編集・削除し、購入時に利用できるよう管理できる。
- 退会内容を確認して退会手続きを行える。

## 2. 入出力項目

| 項目区分 (入力/出力) | 項目名 | 説明 |
|---|---|---|
| 入力 | HTTP セッションのログイン会員情報 | 各マイページ機能で会員を識別する。未ログインの場合は HTTP 401 を返す。 |
| 入力 | クエリパラメータ `page` | 注文履歴、お気に入り、追加お届け先一覧のページ番号。省略時は `1`。 |
| 入力 | URL パス変数 `orderNumber` | 注文履歴詳細または再注文の対象となる注文番号。 |
| 入力 | URL パス変数 `memberAddressId` | 表示・更新・削除する追加お届け先の ID。 |
| 入力 | 会員情報フォーム `profileForm` | 個人／法人区分、氏名・氏名カナ、会社名・部署名、メールアドレス、性別、生年月日／記念日、メールマガジン希望、郵便番号、住所、配送階数、エレベーター有無、日中連絡先電話番号、FAX。 |
| 入力 | 追加お届け先フォーム `addressForm` | 氏名・氏名カナ、会社名・部署名、郵便番号、住所、配送階数、エレベーター有無、日中連絡先電話番号、FAX。 |
| 入力 | HTTP リクエスト／レスポンス | 注文履歴から商品を再びカートに追加する際に使用する。 |
| 出力 | 遷移先 `redirect:/mypage/orders` | `/mypage` にアクセスした場合の既定遷移先。 |
| 出力 | 遷移先 `pages/mypage-orders-list` | 注文履歴一覧。モデル `orders`、`currentPage`、`totalPages` を渡す。 |
| 出力 | 遷移先 `pages/mypage-order-detail` | 注文履歴詳細。モデル `orderDetail` に対象注文情報を渡す。対象がない場合は HTTP 404。 |
| 出力 | 遷移先 `redirect:/cart` | 再注文した商品のカート追加後の遷移先。 |
| 出力 | フラッシュ属性 `cartMessage` | 再注文商品の追加成功を知らせるメッセージ。 |
| 出力 | フラッシュ属性 `cartError` | 再注文できる商品がない場合、または一部商品の追加に失敗した場合の案内。 |
| 出力 | 遷移先 `pages/mypage-favorites` | お気に入り一覧。モデル `favorites`、`favoriteCount`、`favoriteLimit`、`currentPage`、`totalPages` を渡す。 |
| 出力 | 遷移先 `pages/mypage-profile-edit` | 会員情報変更画面。モデル `profileForm` に現在の会員情報または送信されたフォームを渡す。 |
| 出力 | 入力検証結果 | 会員情報に不備がある場合、項目別エラーを画面へ表示する。登録済みメールアドレスや法人会員の会社名不足も検証対象。 |
| 出力 | フラッシュ属性 `profileUpdatedMessage` | 会員情報の更新完了を知らせるメッセージ。 |
| 出力 | 遷移先 `redirect:/mypage/profile` | 会員情報の更新後の遷移先。 |
| 出力 | 遷移先 `pages/mypage-addresses` | 追加お届け先一覧。モデル `addresses`、`addressCount`、`addressLimit`、`addressLimitReached`、`currentPage`、`totalPages` を渡す。 |
| 出力 | 遷移先 `pages/mypage-address-form` | 追加お届け先の新規登録・編集画面。モデル `addressForm`、`formAction`、`isEditMode`、`cancelUrl` を渡す。 |
| 出力 | 画面モデル `addressLimitError` | 追加お届け先の新規登録画面で、登録上限に達していることを知らせる案内。 |
| 出力 | フラッシュ属性 `addressLimitError` | 追加お届け先の登録時に上限を超えた場合、一覧画面で表示するエラーメッセージ。 |
| 出力 | 入力検証結果 | 追加お届け先に不備がある場合、項目別エラーを画面へ表示する。法人会員の会社名も検証対象。 |
| 出力 | 遷移先 `redirect:/mypage/addresses` | 追加お届け先の登録・更新・削除後の一覧画面。 |
| 出力 | HTTP 404 | 指定された注文または追加お届け先が見つからない場合に返す。 |
| 出力 | HTTP 401 | ログインしていない状態でマイページ機能にアクセスした場合に返す。 |
| 出力 | 遷移先 `pages/mypage-withdraw` | 退会確認画面。 |
| 出力 | 遷移先 `redirect:/login` | 退会処理後のログイン画面。会員セッションを破棄する。 |

## 3. 処理フロー

### `mypageTop`（GET `/mypage`）

1. `redirect:/mypage/orders` へリダイレクトする。

### `orders`（GET `/mypage/orders`）

1. セッションからログイン会員を取得する。未ログインの場合は HTTP 401 の例外を送出する。
2. `OrderService` を呼び出して、指定ページの購入履歴を取得する（`page` の省略時は `1`）。
3. 購入履歴が存在し、取得結果が空で、指定ページが総ページ数を超えている場合：
   1. 総ページ数を指定して `OrderService` を再度呼び出す。
   2. 再取得したページ情報に合わせて現在ページと総ページ数を更新する。
4. 注文一覧、現在ページ、総ページ数を画面モデルに設定する。
5. 注文履歴一覧画面 `pages/mypage-orders-list` を返す。

### `orderDetail`（GET `/mypage/orders/{orderNumber}`）

1. セッションからログイン会員を取得する。未ログインの場合は HTTP 401 の例外を送出する。
2. `OrderService` を呼び出して、会員 ID と注文番号に一致する注文詳細を取得する。
3. 注文詳細が見つからない場合：
   1. 注文詳細が見つからなかったことを警告ログに記録する。
   2. HTTP 404 の例外を送出する。
4. 注文詳細を画面モデル `orderDetail` に設定する。
5. 注文履歴詳細画面 `pages/mypage-order-detail` を返す。

### `reorder`（POST `/mypage/orders/{orderNumber}/reorder`）

1. セッションからログイン会員を取得する。未ログインの場合は HTTP 401 の例外を送出する。
2. `OrderService` を呼び出して、注文番号が会員の購入履歴に存在するか確認する。
3. 注文が見つからない場合：
   1. 再注文の拒否を警告ログに記録する。
   2. HTTP 404 の例外を送出する。
4. `OrderService` を呼び出して再購入対象の商品一覧を取得する。
5. 商品ごとにカートへの追加を試みる。
   - 商品バリエーション ID がない、または数量が 0 以下の場合：追加失敗商品として記録し、次の商品へ進む。
   - `CartService` の追加処理が `IllegalArgumentException` を送出した場合：追加失敗商品として記録し、次の商品へ進む。
   - カートへの追加に成功した場合：成功件数を加算する。
6. 追加成功件数が 0 件の場合：
   1. 再注文できる商品がないことを示すフラッシュ属性 `cartError` を設定する。
   2. `redirect:/cart` へリダイレクトする。
7. 1 件以上追加できた場合：
   1. 成功メッセージをフラッシュ属性 `cartMessage` に設定する。
   2. 追加失敗商品がある場合：失敗商品コードを含むメッセージをフラッシュ属性 `cartError` に設定する。
   3. `redirect:/cart` へリダイレクトする。

### `favorites`（GET `/mypage/favorites`）

1. セッションからログイン会員を取得する。未ログインの場合は HTTP 401 の例外を送出する。
2. `MemberService` を呼び出して、指定ページのお気に入り一覧を取得する（`page` の省略時は `1`）。
3. お気に入りが存在し、取得結果が空で、指定ページが総ページ数を超えている場合：
   1. 総ページ数を指定して `MemberService` を再度呼び出す。
   2. 再取得したページ情報に合わせて現在ページと総ページ数を更新する。
4. お気に入り一覧、件数、上限数、現在ページ、総ページ数を画面モデルに設定する。
5. お気に入り一覧画面 `pages/mypage-favorites` を返す。

### `profileEdit`（GET `/mypage/profile`）

1. セッションからログイン会員を取得する。未ログインの場合は HTTP 401 の例外を送出する。
2. 画面モデルに `profileForm` が設定されていない場合：
   1. `MemberService` を呼び出して会員情報変更フォームを取得する。
   2. 会員情報が見つからない場合は HTTP 404 の例外を送出する。
   3. 取得したフォームを画面モデル `profileForm` に設定する。
3. 会員情報変更画面 `pages/mypage-profile-edit` を返す。

### `updateProfile`（POST `/mypage/profile`）

1. セッションからログイン会員を取得する。未ログインの場合は HTTP 401 の例外を送出する。
2. 送信された会員情報フォームを正規化し、会員種別に応じた入力条件を検証する。
   - 法人会員で会社名が未入力または空白の場合：会社名の入力エラーを追加する。
3. 入力エラーがある場合：
   1. 入力エラーを警告ログに記録する。
   2. 会員情報変更画面 `pages/mypage-profile-edit` を返す。
4. `MemberService` を呼び出して会員情報を更新する。
5. メールアドレスが重複している場合：
   1. メールアドレスの重複エラーを追加する。
   2. 会員情報変更画面 `pages/mypage-profile-edit` を返す。
6. 更新に成功した場合：
   1. `MemberService` を呼び出して更新後の有効な会員情報を取得する。
   2. 会員情報が取得できた場合：`MemberSessionService` を呼び出してログインセッションを更新する。
   3. 更新完了メッセージをフラッシュ属性 `profileUpdatedMessage` に設定する。
   4. `redirect:/mypage/profile` へリダイレクトする。

### `addresses`（GET `/mypage/addresses`）

1. セッションからログイン会員を取得する。未ログインの場合は HTTP 401 の例外を送出する。
2. `MemberService` を呼び出して、指定ページの追加お届け先一覧を取得する（`page` の省略時は `1`）。
3. 追加お届け先が存在し、取得結果が空で、指定ページが総ページ数を超えている場合：
   1. 総ページ数を指定して `MemberService` を再度呼び出す。
   2. 再取得したページ情報に合わせて現在ページと総ページ数を更新する。
4. 追加お届け先件数が上限以上かを判定する。
5. 一覧、件数、上限数、上限到達状態、現在ページ、総ページ数を画面モデルに設定する。
6. 追加お届け先一覧画面 `pages/mypage-addresses` を返す。

### `addressNewForm`（GET `/mypage/addresses/new`）

1. セッションからログイン会員を取得する。未ログインの場合は HTTP 401 の例外を送出する。
2. `MemberService` を呼び出して、追加お届け先の登録上限に達しているか確認する。
3. 登録上限に達している場合：
   1. 上限到達を警告ログに記録する。
   2. 上限超過メッセージを画面モデル `addressLimitError` に設定する。
4. 画面モデルに `addressForm` が設定されていない場合、新しい入力フォームを設定する。
5. 登録画面用のフォームアクション、編集モード、キャンセル先を画面モデルに設定する。
6. 追加お届け先フォーム画面 `pages/mypage-address-form` を返す。

### `addressEditForm`（GET `/mypage/addresses/{memberAddressId}/edit`）

1. セッションからログイン会員を取得する。未ログインの場合は HTTP 401 の例外を送出する。
2. `MemberService` を呼び出して、指定 ID の追加お届け先を取得する。
3. 追加お届け先が見つからない場合：
   1. 対象が見つからなかったことを警告ログに記録する。
   2. HTTP 404 の例外を送出する。
4. 画面モデルに `addressForm` が設定されていない場合、取得したお届け先情報を入力フォームへ変換して設定する。
5. 編集画面用のフォームアクション、編集モード、キャンセル先を画面モデルに設定する。
6. 追加お届け先フォーム画面 `pages/mypage-address-form` を返す。

### `createAddress`（POST `/mypage/addresses`）

1. セッションからログイン会員を取得する。未ログインの場合は HTTP 401 の例外を送出する。
2. 送信された追加お届け先フォームを正規化し、会員種別に応じた入力条件を検証する。
   - 法人会員で会社名が未入力または空白の場合：会社名の入力エラーを追加する。
3. 入力エラーがある場合：
   1. 入力エラーを警告ログに記録する。
   2. 登録画面用のフォームアクションなどを画面モデルに設定する。
   3. 追加お届け先フォーム画面 `pages/mypage-address-form` を返す。
4. `MemberService` を呼び出して追加お届け先を登録する。
5. 登録上限を超過した場合：
   1. 上限超過を警告ログに記録する。
   2. 上限超過メッセージをフラッシュ属性 `addressLimitError` に設定する。
   3. `redirect:/mypage/addresses` へリダイレクトする。
6. 登録に成功した場合、`redirect:/mypage/addresses` へリダイレクトする。

### `updateAddress`（POST `/mypage/addresses/{memberAddressId}`）

1. セッションからログイン会員を取得する。未ログインの場合は HTTP 401 の例外を送出する。
2. `MemberService` を呼び出して、指定 ID の追加お届け先が会員に属するか確認する。
3. 追加お届け先が見つからない場合：
   1. 対象が見つからなかったことを警告ログに記録する。
   2. HTTP 404 の例外を送出する。
4. 送信されたフォームを正規化し、会員種別に応じた入力条件を検証する。
   - 法人会員で会社名が未入力または空白の場合：会社名の入力エラーを追加する。
5. 入力エラーがある場合：
   1. 入力エラーを警告ログに記録する。
   2. 編集画面用のフォームアクションなどを画面モデルに設定する。
   3. 追加お届け先フォーム画面 `pages/mypage-address-form` を返す。
6. `MemberService` を呼び出して追加お届け先を更新する。
7. 更新対象が見つからず更新できなかった場合：
   1. 更新時に対象が見つからなかったことを警告ログに記録する。
   2. HTTP 404 の例外を送出する。
8. 更新に成功した場合、`redirect:/mypage/addresses` へリダイレクトする。

### `deleteAddress`（POST `/mypage/addresses/{memberAddressId}/delete`）

1. セッションからログイン会員を取得する。未ログインの場合は HTTP 401 の例外を送出する。
2. `MemberService` を呼び出して指定 ID の追加お届け先を削除する。
3. `redirect:/mypage/addresses` へリダイレクトする。

### `withdraw`（GET `/mypage/withdraw`）

1. セッションからログイン会員を取得する。未ログインの場合は HTTP 401 の例外を送出する。
2. 退会確認画面 `pages/mypage-withdraw` を返す。

### `withdrawExecute`（POST `/mypage/withdraw`）

1. セッションからログイン会員を取得する。未ログインの場合は HTTP 401 の例外を送出する。
2. `MemberService` を呼び出して会員を退会させる。
3. `MemberSessionService` を呼び出して会員セッションを破棄する。
4. `redirect:/login` へリダイレクトする。
