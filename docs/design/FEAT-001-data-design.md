# FEAT-001 データ設計

## 1. 対象データ

検索対象として、以下のデータを利用する。

- products.code
- products.name
- products.series_name
- products.description

必要に応じて、関連する商品詳細・カテゴリ情報も検索条件に含める。

## 2. 検索条件のデータ構造

既存の ProductSearchCondition を拡張して、検索キーワードと絞り込み条件を保持する。

### 2.1 既存の主な項目

- keyword
- categoryId
- inStockOnly
- priceBands
- colorIds
- categoryFilter
- sort
- page
- size

### 2.2 追加予定の考慮点

- 検索キーワードの正規化済み値
- テイスト絞り込み条件のリスト
- 0件時メッセージ表示のための判定フラグ

## 3. SQL設計

### 3.1 商品コード検索

- 完全一致: `=`
- 前方一致: `LIKE 'keyword%'`
- 中間一致: 使用しない

### 3.2 商品名・シリーズ名・説明文検索

- 部分一致条件として `LIKE '%keyword%'` を使用する
- 文字列比較の前に正規化を適用する

### 3.3 テイスト絞り込み

既存のカテゴリ一覧で実装済みの「テイスト」絞り込み条件を再利用し、検索条件に AND 条件として結合する。

## 4. ページネーション設計

- 1ページ件数は既存一覧画面に合わせる
- 超過分はページネーションで表示する
- 総件数を取得した上で、結果一覧とページ情報を返す

## 5. 性能設計

- まずは既存の検索条件構造と SQL を活用する
- 検索件数が増えた場合、以下を検討する
  - 正規化済みカラムの追加
  - インデックスの追加
  - 全文検索の導入

## 6. データ整合性

- 検索キーワードの前後空白はトリムして保存・比較する
- 空入力時は検索条件を未設定として扱う
- 文字正規化ルールはアプリケーション側とDB側で統一する
