## 1. テスト方針

### 1-1. テスト種別と対象

| 種別 | 主な対象 | ツール |
|------|---------|-------|
| ユニットテスト（UT） | `NormalizationUtils`、`ProductRepository.buildKeywords()`、`ProductFilterOptionService.normalizeTasteDisplayNames()` | JUnit 5 + AssertJ |
| 統合テスト（IT） | `ProductMapper` SQL（キーワード検索・テイストフィルタ）、`ProductRepository.search()` | `@MybatisTest` または `@SpringBootTest` + TestContainers |
| E2E / 受け入れテスト | 検索結果一覧画面の全フィルタ組み合わせ | ブラウザ手動テスト or Playwright |

### 1-2. 前提・制約

- キーワード正規化（`NormalizationUtils`）は DB に依存しないため、純粋な UT で網羅する。
- SQL レベルの動作確認（ILIKE / 前方一致 / テイスト EXISTS）は統合テストで行い、実 PostgreSQL または TestContainers を使用する。
- 性能テスト（95 パーセンタイル 2 秒以内）の計測は本テスト設計書のスコープ外。別途負荷テストで確認する。
