### D-01　最近見た商品IDの取得方式を確認します

- **ステータス**: 回答済み（**案1 採用**）
- **背景**: セクション B（カート）およびセクション C（トップ）の推薦起点として「最近見た商品ID」をサーバーサイドで必要とします。現状の `/products/recently-viewed` API はクライアント JS が `ids` クエリパラメータとして渡す設計です。サーバー側レンダリング（`GET /cart`・`GET /`）では直接 ID を受け取れないため、取得方式の確認が必要です。
- **影響範囲**: `HomeController.top()`・`CartController.cart()` の実装方式、およびシーケンス図の `Session` 参照箇所

| 候補 | 実装概要 | メリット | デメリット |
|-----|---------|--------|---------|
| **案1: HttpSession 経由** | 商品詳細ページ表示時に `CatalogController` がセッションへ商品IDリストを書き込む。カート・トップでセッションから読み取る | 既存コードに近い（シーケンス図に「Session: 最近見た商品リストを更新」の記述あり） | セッション有効期限切れで消える。複数端末間で共有されない |
| **案2: JavaScript Cookie から直接読み取り** | JS が書き込んだ Cookie（例: `recently_viewed`）を `HttpServletRequest.getCookies()` でサーバー側に読み取る | 既存の Cookie 設計を活用できる場合は変更不要 | Cookie 名・フォーマットの確認が必要。JS 側で Cookie として書き込む実装があるかどうかを確認する必要がある |
| **案3: JS による非同期読み込み（遅延表示）** | 基本ページをサーバーサイドでレンダリング後、JS がお薦めセクションを API 経由で非同期取得・描画する | 既存の `/products/recently-viewed` API を流用できる | ページ表示後にセクションが遅れて表示される。新規 API エンドポイントまたは既存 API の拡張が必要 |

**解答欄**:
```
案1（HttpSession 経由）を採用。
商品詳細ページ表示時に CatalogController.productDetail() がセッションキー
"recently_viewed_product_ids" に List<Long>（最大8件）を書き込む。
カート・トップ画面でセッションから読み取る。
```

### D-02　`recommended_related_products` のインデックス状況を確認します

- **ステータス**: 回答済み（**インデックス追加**）
- **背景**: 今回の実装では `source_product_id` を絞り込み条件に使い、加えて `recommendation_date` の最大値でフィルタします。この組み合わせを高速に処理するための複合インデックスがなければクエリが遅くなる可能性があります。
- **影響範囲**: `sql/schema/` または `sql/init/` へのインデックス追加 SQL の追記

| 確認ポイント | 内容 |
|------------|------|
| 現行インデックス | `recommended_related_products` テーブルに `(source_product_id, recommendation_date)` の複合インデックスは存在しますか？ |
| 追加要否 | 1,000 件規模であれば影響は軽微ですが、追加推奨かどうかを判断してください |

**解答欄**:
```
複合インデックスは未存在のため追加する。
CREATE INDEX IF NOT EXISTS idx_rrp_source_date
  ON recommended_related_products(source_product_id, recommendation_date DESC);
sql/schema/products.sql に追記。
```

### D-03　注文履歴から商品IDを解決するSQL結合の可否を確認します

- **ステータス**: 回答済み（**INNER JOIN 採用**）
- **背景**: `order_items` は商品コードのスナップショット（`product_code` 文字列）を保持しており、`products.product_id`（Long）との直接結合ができません。詳細設計書では `order_items.product_code` → `product_variants.product_code` → `products.product_id` と辿る結合を想定しています。
- **影響範囲**: `OrderMapper.xml` の購入履歴取得 SQL

| 確認ポイント | 内容 |
|------------|------|
| `product_variants.product_code` の一意性 | 商品コードは `product_variants` で一意制約（UNIQUE）が付いていますか？スナップショット時との整合性に問題はありませんか？ |
| 削除・廃番商品 | 廃番になり `product_variants` から削除された商品コードが `order_items` に残る場合、INNER JOIN では見つからずゼロ件になりますが、それで問題ありませんか？ LEFT JOIN に変えますか？ |

**解答欄**:
```
INNER JOIN で問題なし。廃番商品が order_items に残っていても
product_variants から削除済みならゼロ件になるが、推薦精度への影響は軽微。
order_items.product_code → product_variants.product_code → products.product_id の結合経路を採用。
```

### D-04　`ProductCardView` への `inStock` フラグ追加の要否を確認します

- **ステータス**: 回答済み（**変更不要**）
- **背景**: お薦めセクションでは在庫切れ商品も表示し、カード上で「在庫切れ」状態を明示します（要件定義書 §4-A-2・§4-B-2・§4-C-3）。現行の `ProductCardView` に在庫状態を示すフィールドが存在するかどうかを確認します。存在しない場合は追加が必要です。

| 確認ポイント | 内容 |
|------------|------|
| 現行 `ProductCardView` | `inStock`・`stockQuantity` などの在庫状態フィールドはありますか？ |
| 追加が必要な場合 | `ProductCardView`・対応 SQL・テンプレートに在庫フラグを追加することになります |

**解答欄**:
```
ProductCardView にはすでに boolean inStock フィールドが存在する（ProductRepository.toCard() で maxStock > 0 により設定済み）。
追加不要。テンプレート側でバッジ表示のみ追加する。
```

### D-05　お薦め商品カードの横スクロール vs グリッドを確認します

- **ステータス**: 回答済み（**A・B は carousel、C は grid**）
- **背景**: 要件定義書では「横スクロールまたはグリッド」と記載しています。実際のレイアウト（PC・モバイル）のどちらにするか、既存の商品カード行レイアウトと統一するかどうかを確認します。
- **影響範囲**: `CUSTOM-001-screen-design.md` の CSS クラス名指定・テンプレート

| 対象 | 推奨案 | 確認 |
|-----|-------|-----|
| セクション A・B（最大4件） | 横スクロール（`product-card-row`） | |
| セクション C（最大8件） | グリッド2列×4行（`product-card-grid`） | |

**解答欄**:
```
セクション A（商品詳細）・セクション B（カート）は carousel（既存の売れ筋ランキングと同じ横スクロール方式）。
セクション C（トップ）は grid grid--4（4列×2行 最大8件）。
```

- **ステータス**: 回答済み（**売れ筋ランキング下部**）
- **背景**: 要件定義書では「最近見た商品セクションの下部」と定義していますが、現在のトップページのセクション順序（新着商品・売れ筋ランキング・最近見た商品等）の詳細は Thymeleaf テンプレートで確認が必要です。
- **影響範囲**: `top.html` の挿入位置

| 現在のセクション順（推定） | 変更後 |
|----------------------|------|
| ① 新着商品 | ① 新着商品 |
| ② 売れ筋ランキング | ② 売れ筋ランキング |
| ③ 最近見た商品 | ③ 最近見た商品 |
|  | ④ **超マジお薦め**（会員限定・★追加） |

**解答欄**:
