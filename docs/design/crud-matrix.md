# CRUD マトリクス

本ドキュメントは、office-order システムにおける機能/処理単位とデータベーステーブルの CRUD 関係を整理した設計資料です。

---

## 凡例

| 記号       | 意味                                |
| ---------- | ----------------------------------- |
| C          | 作成（INSERT）                      |
| R          | 参照（SELECT）                      |
| U          | 更新（UPDATE）                      |
| D          | 削除（DELETE）                      |
| 組み合わせ | 例：CR = 参照 + 作成、CRUD = 全操作 |
| —          | アクセスなし                        |

## 6. Spring Batch メタデータテーブル

Spring Batch フレームワークがジョブ実行時に自動管理するメタデータテーブルです。アプリケーションのビジネスロジックから直接アクセスされるわけではなく、Spring Batch のインフラストラクチャが透過的に読み書きします。

| No. | 機能/処理                    | batch_job_instance | batch_job_execution | batch_job_execution_params | batch_job_execution_context | batch_step_execution | batch_step_execution_context |
| --- | ---------------------------- | :----------------: | :-----------------: | :------------------------: | :-------------------------: | :------------------: | :--------------------------: |
| 17  | バッチ: 売れ筋ランキング集計 |         C          |         CU          |             C              |             CU              |          CU          |              CU              |
| 18  | バッチ: おすすめ関連商品集計 |         C          |         CU          |             C              |             CU              |          CU          |              CU              |

> - ジョブ開始時に `batch_job_instance`・`batch_job_execution`・`batch_job_execution_params` が INSERT される。
> - ジョブ終了時に `batch_job_execution`・`batch_step_execution` のステータスが UPDATE される。
> - `batch_job_execution_context` と `batch_step_execution_context` は実行中に繰り返し CU される。

## 設計上の注意点

| 項目                 | 内容                                                                                                                                                                                     |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 読み取り専用テーブル | `products`・`product_variants`・各マスタテーブル・`tax_rates`・`announcements` はアプリケーションから UPDATE/DELETE されない。データ変更は DB 管理者または別途の管理機能が担当する想定。 |
| 論理削除             | `members` の退会処理は物理削除ではなく `member_status='withdrawn'` への UPDATE（論理削除）。                                                                                             |
| スナップショット設計 | `order_items` は注文確定時点の商品名・単価・税率をスナップショットとして保持するため、注文履歴表示時に `products` を参照しない。                                                         |
| クッキーカート       | カートデータは DB テーブルではなくクッキーで管理されるため、カート操作に対応するテーブルは存在しない。                                                                                   |
| バッチの洗い替え方式 | `popular_product_rankings`・`recommended_related_products` はバッチ実行ごとに DELETE → INSERT の洗い替えを行う。中間的な U 操作は発生しない。                                            |
| 採番テーブル         | `order_number_counters` は注文番号の採番用途に特化しており、注文確定時のみ CU が発生する。                                                                                               |
