# FEAT-001: 商品検索機能強化 設計書（UI/UX）

## 1. 目的

- 検索機能強化に伴う画面変更と操作フローを設計し、要件通りのユーザー体験を定義する。

## 2. 対象画面

- ヘッダ検索ボックス
- 検索結果ページ (`product-list-search-results.html`)

## 3. ヘッダ検索ボックス

- 既存の検索フォームをそのまま利用する。
- `q` パラメータで検索文字列を送信する。
- プレースホルダは `商品名・商品コード` のまま維持する。

## 4. 検索結果ページの変更

### 4.1 絞り込みパネル

- 検索結果画面に「テイスト」絞り込みセクションを追加する。
- 形式: 複数選択可能なチェックボックスリスト
- 表示順: 既存カテゴリ一覧のテイスト候補と同じ仕様に準拠する。
- モバイルは既存のモーダル / 条件絞り込み UI を利用し、テイスト項目を追加する。

### 4.2 検索キーワード表示

- 検索結果上部に入力キーワードを表示する。
- 未入力時は `（未入力）` を表示する。

### 4.3 0件メッセージ

- 検索結果が 0 件の場合、画面に以下メッセージを表示する。
  - `該当する商品がありませんでした。`
- メッセージ表示領域は既存の空結果表示位置を流用する。

### 4.4 既存の検索結果表示と併合

- ソート順、ページング、表示件数、在庫絞り込みなどの既存仕様はそのまま継承する。
- 検索条件のリセットは既存の `q=${keyword}` リンクを活用する。

### 4.5 画面パラメータ

- `q`: 検索キーワード
- `inStockOnly`: 在庫ありのみ
- `priceBand`: 価格帯
- `color`: カラー
- `sort`: 並び順
- `page`: ページ番号
- `size`: 表示件数
- `taste`: テイスト選択

## 5. フロントエンド操作フロー

1. ヘッダ検索フォームにキーワードを入力し検索を実行。
2. 検索結果ページに遷移し、キーワードと絞り込み UI を表示。
3. ユーザーがテイストチェックボックスを選択して再検索。
4. キーワードとテイストの組み合わせは AND 条件で結果を絞り込む。
5. 0 件の場合、指定メッセージを表示する。

## 6. アクセシビリティ

- `aria-label` 付きのフォーム要素を維持する。
- フィルタのチェックボックスはラベルとセットで表示し、選択状態を明確にする。

## 7. 既存仕様との整合性

- カテゴリ一覧のテイスト絞り込み UI と同じ操作感を目指す。
- 既存の検索 UI を大きく変更しない。
