# FEAT-001 検索機能設計

## 1. 概要

本設計では、ヘッダー検索ボックスから入力されたキーワードを、要件に沿って検索し、検索結果一覧画面へ反映するための処理設計を定義する。

## 2. 対象範囲

- 検索キーワードの受け取り
- 入力値正規化
- 検索条件の構築
- 商品検索ロジック
- 検索結果のソート・ランキング
- 空入力・0件時の処理

## 3. 画面からの入力フロー

1. ヘッダー検索フォームからキーワードを受け取る。
2. Controller で検索条件を生成する。
3. Service 層で入力値を正規化し、検索条件を構築する。
4. Repository / Mapper で検索を実行する。
5. 検索結果を一覧画面へ表示する。

## 4. 検索ロジック

### 4.1 文字正規化

検索入力値に対して、以下を行う。

- 前後空白を除去
- 全角/半角の英数字・カタカナを正規化する
- 英字を小文字化する

実装方針としては、Java 側で NFKC などの標準的な正規化処理を適用し、DB 比較時も同じルールを用いる。

### 4.2 検索対象

以下の項目を検索対象とする。

- 商品コード
- 商品名
- シリーズ名
- 説明文

### 4.3 条件別一致ルール

- 商品コード
  - 完全一致
  - 前方一致
  - 中間一致は不可
- 商品名 / シリーズ名 / 説明文
  - 部分一致
  - 大文字小文字を区別しない
  - 全角半角を区別しない

### 4.4 優先順位

検索結果は以下の順で優先表示する。

1. 商品コード一致
2. 商品名一致
3. シリーズ名一致
4. 説明文一致

## 5. 既存実装への適用方針

### 5.1 対象クラス

- CatalogController
  - /products/search でキーワードを受け取り、検索条件を生成する
- ProductListSearchService
  - キーワード入力の正規化と検索条件組み立てを担当する
- ProductService
  - 商品一覧検索の呼び出しを担当する
- ProductRepository
  - SQL パラメータを構築し、検索結果を返す
- ProductMapper
  - SQL で検索条件に応じた取得を行う

### 5.2 追加想定クラス

- SearchKeywordNormalizer
  - 入力文字列の正規化処理を担当
- SearchQueryBuilder
  - 商品コード/商品名/シリーズ/説明文の条件式を組み立てる

## 6. 空入力・不正入力時の扱い

- 空文字またはスペースのみの入力は、既存のヘッダー検索挙動に合わせて扱う
- 既定では検索を実行しないか、既存一覧画面を表示する
- 前後空白は自動で除去する

## 7. 0件時の表示

検索結果が 0 件の場合、以下のメッセージを表示する。

- 該当する商品が見つかりませんでした。別のキーワードでお試しください。

## 8. 性能方針

- 検索対象件数は 1000 件程度を想定する
- 1 ページ表示件数は既存一覧画面に合わせる
- ページネーションを用いて初回表示の負荷を抑える
- 必要に応じて、DB 側で正規化済みカラムやインデックスの追加を検討する

## 9. リスクと留意点

- 商品コード検索における前方一致/完全一致の制御を SQL で厳密に実装する必要がある
- 大文字小文字・全角半角の差異を、アプリケーション側とDB側で同じルールで吸収する必要がある
- テイスト絞り込みとのAND条件の扱いを明確化する必要がある
