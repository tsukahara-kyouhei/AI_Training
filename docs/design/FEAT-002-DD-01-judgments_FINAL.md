# FEAT-002: 設計判断・アーキテクチャ方針（最終版）

## 1. 最終判断一覧

| No | 項目 | 最終仕様 |
|---:|---|---|
| 1 | キャンセル・返品 | 注文状態で管理。`returned` を追加。返品は注文単位、部分返品なし。状態遷移成功を返還トリガーとし二重返還を防止。 |
| 2 | クーポン状態 | セッションに保存。クライアントCookieには保存しない。 |
| 3 | ゲスト | `max_usage_per_user` 設定クーポンは利用不可。未設定クーポンは利用可。ゲストの会員別実績は作成しない。 |
| 4 | 金額 | 整数円。税額はクーポン割引後の商品小計を基準にする。送料無料判定は割引前の既存条件を維持する。明細割引は対象商品の小計比で配賦し、剰余の大きい順（同率は明細順）に整数円の残額を配る。明細税は配賦後の金額を既存税率・切り捨てで計算し、ヘッダーとの差を追加調整しない。 |
| 5 | FK・削除 | FKは `RESTRICT` / `NO ACTION`。クーポン物理削除は禁止し `is_active=false` で無効化。 |
| 6 | JSON不正 | `target_conditions` の構造不正は登録時に拒否。既存不正データは適用対象外。 |

## 2. クーポン条件

```json
{
  "allowed_category_ids": ["desk", "chair"],
  "allowed_product_ids": [100, 105],
  "target_user_type": "all"
}
```

- カテゴリ条件と商品条件はOR。
- 両配列が空なら対象商品なしとして不成立。
- 一方だけ空なら値がある側だけで判定。
- `target_user_type` は `all` / `new`。
- `new` は対象会員の `completed` 注文数0件。
- 会員ランク条件は今回対象外。
- 3キーは必須。欠落、null、配列型不正、要素型不正、許容値外、不正JSONは登録時に拒否する。
- `allowed_category_ids` の要素は既存 `products.category_id` の許容値 `desk` / `chair` / `storage`。
- `allowed_product_ids` の要素は正の整数の `products.product_id`。
- 商品／カテゴリ配列の空配列はその条件では一致なし。両方空なら対象商品なしとして不成立。
- 未知キーと、登録時に存在しない `product_id` を拒否するかは人間判断事項。

## 3. 割引計算

1. 対象商品をOR条件で抽出。
2. `target_subtotal = 単価 × 数量` の合計。
3. `target_subtotal >= min_purchase_amount` を判定。
4. 定額は `discount_value`。
5. 定率は `FLOOR(target_subtotal × discount_value / 100)`。
6. `max_discount_amount` は定率のみ適用。
7. `final_discount = MIN(算出割引額, target_subtotal)`。
8. 送料・手数料は割引対象外。
9. 金額は整数円。

対象商品が0円でも商品が存在すれば対象条件は成立し、最低購入金額は別途判定する。

## 3.1 注文金額・税・送料

記号:
- `P`: クーポン適用前の商品小計
- `T`: クーポン対象商品の小計
- `D`: 算出したクーポン割引額
- `A`: 組立費合計
- `r`: 現行の有効税率
- `S`: 送料

計算:
1. `P` はカート商品単価×数量の合計。
2. `T` は対象商品単価×数量の合計。最小購入金額と割引計算の対象。
3. `D = MIN(クーポン算出割引額, T)`。
4. `P' = P - D`。
5. `Tax = FLOOR((P' + A) × r / 100)`。
6. 送料判定には割引前の課税対象小計 `P + A` とその税額 `FLOOR((P + A) × r / 100)` を使う。既存条件のとおり税込み金額が5,000円以上なら `S=0`、未満なら `S=800`。割引後に送料を再判定しない。
7. `OrderTotal = P' + A + Tax + S`。

実装方針: `CartService` の送料判定は割引前課税対象小計（商品小計＋組立費）の税込み値で行い、クーポン再計算後も送料を保持する。注文ヘッダー税額は割引後商品小計と組立費を基準にし、明細割引はクーポン対象商品小計に比例配賦する。整数円の配賦端数は剰余の大きい明細から配り、同率はカート内明細順とする。明細税額は配賦後の課税対象金額を既存税率・切り捨てで計算し、明細単位切り捨てによるヘッダーとの差は追加調整しない。

## 4. クーポン状態

- 適用中クーポンコードと適用時の `member_id`（ゲストはNULL）をセッションに保存する。
- 商品カートCookieには混在させない。
- 割引額はセッション保存値を確定金額として扱わず、確認・確定時にサーバー側で再計算する。
- 商品追加・削除・数量変更・カート全削除後もコードを保持する。注文確認GET時に現在のカートで再検証し、不成立なら解除する。
- 会員変更時はコードと会員識別情報を解除する。別会員で使う場合は再適用する。
- セッション失効時にはセッション内のクーポン状態も失われる。ログアウト時の現行実装はセッションを無効化する。

## 5. ゲスト

- `member_id IS NULL` のゲスト注文を許容する。
- `max_usage_per_user` が設定されたクーポンはゲスト適用不可。
- `max_usage_per_user` が未設定ならゲスト利用可能。
- ゲストの `user_coupon_usages` 行は作成しない。
- ゲスト利用時も全体利用上限は適用する。

## 6. 注文スナップショット

注文確定時に以下を保存する。
- `applied_coupon_code`
- `applied_coupon_name`
- `coupon_discount_amount`

クーポンマスタ無効化後も注文履歴はこのスナップショットを表示する。
既存 `orders.subtotal_amount` はクーポン割引前の商品小計のままとし、割引額は独立した `coupon_discount_amount` に保存する。

## 7. キャンセル・返品

- キャンセルは既存の `cancelled` 状態への遷移として扱う。
- 返品は `returned` 状態を追加する。
- `orders.order_status` と `order_status_histories.status` の両方で管理する。
- 返品は注文単位とし、部分返品は対象外。
- `cancelled` または `returned` への状態遷移が成功した場合に1回だけ利用実績を返還する。
- 既に対象状態の注文を再処理しても返還しない。
- 許可する遷移元状態と `cancelled`／`returned` 間の相互遷移は人間判断事項。既存実装から一意に定まらない。

## 8. 決済・トランザクション

- 既存の `bank_transfer`、`cash_on_delivery`、`convenience_store` のオフライン決済を使用する。
- 外部決済APIは追加しない。
- 注文確定、再検証、利用実績更新、スナップショット保存を既存DBトランザクション内で処理する。
- ロック順序は `coupons` → `user_coupon_usages`。

## 9. 人間判断事項

- 状態遷移表（各開始状態から `cancelled`／`returned` への可否）。
- APIエラーのHTTPステータスと注文確定失敗時のMVC戻り先・表示内容。
- クーポン登録・編集管理機能をFEAT-002の実装範囲に含めるか。現行コードに管理登録経路はない。
- `target_conditions` の未知キー、および登録時点で存在しない商品IDを拒否するか。
- 注文履歴の一覧・詳細のどちらにsnapshotを表示するか。
- クーポン適用API成功JSONのフィールド名・型と、商品小計／合計に税・送料を含めるか。
- DDLの未定義値（列長、割引率範囲・精度、日時境界、上限値NULLの意味、INDEX/CHECK完全定義）。
- 注文確定時の注文保存・利用数更新・スナップショット保存の相互順序。
