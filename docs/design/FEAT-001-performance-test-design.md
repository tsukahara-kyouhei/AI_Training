# FEAT-001 性能試験設計

## 1. 目的

本設計は、性能要件と性能計測方法を分離し、実測の条件と判定基準を定義する。

## 2. 性能要件の整理

- 要件定義: 「一覧初回表示は 95% のケースで 2 秒以内を目標とする」
- 本性能試験設計: どの条件で、どこを、どの方法で計測するかを定義する

## 3. 実測対象

- Controller からレスポンスが返る時間
- Repository / Mapper の SQL 実行時間
- count + list のトータル時間
- 画面レンダリング完了までの時間

## 4. 実測条件

### 4.1 想定データ量

- 通常: 100〜1,000 件程度
- 目標計測: 1,000 件前後
- 0件検索ケース
- 複数フィルタ適用ケース

### 4.2 パターン

- 商品コード完全一致
- 商品コード前方一致
- 商品名部分一致
- 説明文部分一致
- 価格帯 + カラー + 在庫あり
- テイスト + 価格帯 + カラー
- 0 件検索

## 5. 実施方法

- 代表ケースを各 30〜50 回繰り返し実行
- P95 値を計算し、2 秒以内の割合を確認する
- `sql` 実行時間と画面描画時間を分けて計測する

## 6. 判定基準

- 95% のケースで 2 秒以内を目標とし、過不足を記録する
- 2 秒超えがあっても、都度要因分析を行う
- 結果は性能設計書と分離して管理する

## 7. 監視観点

- `countProducts()` と `selectProducts()` の実行時間
- `LIKE` 条件や `EXISTS` 条件の回数
- `GROUP BY` と `ORDER BY` の負荷
- N+1 になっていないか

## 8. 完了条件

- 実測対象が明確である
- ケース一覧が定義されている
- 判定基準が明確である
- 性能設計と性能テストが分離されている
