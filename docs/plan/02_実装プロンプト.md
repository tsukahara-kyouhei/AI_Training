# 02_実装プロンプト

## 目的
01で確定した計画に基づき、必要最小限の変更で実装する。仕様判断が必要になった場合は推測で進めず、影響を整理する。

## コピペ用プロンプト

```text
以下の共通ルールと指示に従って実装してください。

【共通ルール】
- AI_CODING_RULES.md（実際のファイル名に合わせる）

【今回の対象】
- 機能ID：[対象機能のIDを記載。未採番の場合は「なし」]
- 機能名：[対象の機能名を記載]
- 依頼内容：[今回実装する内容を具体的に記載]
- 要件・設計書：[対象となる要件定義書・設計書のファイルパスを記載。なければ「なし」]
- 01調査結果：[01の調査結果・引き継ぎ資料のファイルパスまたは内容を記載]
- 補足・承認済み判断：[補足事項や承認済みの仕様判断を記載。なければ「なし」]

【開始条件】
1. 01の実装開始ゲートを確認する。
2. 「実装開始不可」の場合はコードを変更せず、不足情報と判断事項を報告する。
3. 01の調査結果と現在のファイル・DB定義に差異がないか確認する。差異がある場合は影響を評価し、仕様判断が必要なら止める。

【実装前】
1. 要件・設計、01の引き継ぎ、共通ルールを確認する。
2. Git状態と差分を確認し、作業前から存在する変更・未追跡ファイルを保護する。
3. 変更予定ファイル、変更しないファイル、関連するテストを確定する。
4. 01で定義した期待結果と実装内容を対応づける。

【実装ルール】
- 要件・承認済み設計・実コード・DB定義を根拠に実装する。
- 必要最小限の変更に限定し、無関係なリファクタリング・命名変更・移動・整形をしない。
- API仕様、DB構造、SQL条件、エラーコード、メッセージ、レスポンスを勝手に変更しない。
- ライブラリ、設定、外部API、DBスキーマを無断で追加・変更しない。
- 既存テストを削除・無効化して通過させない。
- 作業前から存在する差分を上書き・破棄しない。
- Git add / commit / pushは明示的な依頼がない限り実行しない。
- DBテストデータは、接続先・スキーマを確認したうえで許可された隔離環境のみを使用する。
- 01で変更対象外としたファイルを変更する必要が生じた場合は、理由・影響を記録し、仕様変更や対象範囲拡大なら人間の判断を求める。

【実装中の問題】
- 仕様の範囲内で原因と影響が明確な実装不具合は、必要最小限で修正してよい。
- API / DB / ビジネスルール / セキュリティ / トランザクション / ユーザーに見える動作の判断が必要な場合は、勝手に決めず、根拠・選択肢・影響をまとめて報告する。
- 調査で解決できる問題は先に調査し、質問を小分けにしない。
- 実装計画からの差異は理由と影響を記録する。

【実装後】
1. 変更差分と変更ファイルを確認する。
2. コンパイル・ビルドを実行する。
3. 変更箇所に対応するテストを実行する。
4. 失敗時はテスト不備、環境問題、仕様不明、実装不具合を切り分ける。
5. 実装不具合を修正した場合は、影響範囲を追跡し、関連テストを再実行する。
6. 01のテスト計画に対して、実施済み・未実施・追加テストを区別する。
7. 各判定に実行コマンド、終了コード、件数、実際の結果などの証拠を付ける。

【結果区分】
PASS / FAIL / NOT RUN / NOT APPLICABLE / BLOCKED
実行していない確認をPASSとしない。

【報告形式】

## 1. 変更ファイル
| ファイル | 変更内容 | 理由 | 01の計画との差異 |
|---|---|---|---|

## 2. 要件・設計との対応
| 要件・設計項目 | 実装箇所 | 根拠 | 結果 |
|---|---|---|---|

## 3. 横断整合性の更新
01のマトリクスから変化した項目のみ更新し、変化がなければその旨を記載する。

## 4. 実施した確認
| コマンド・確認 | 結果区分 | 終了コード・件数 | 証拠・補足 |
|---|---|---|---|

## 5. 影響範囲と回帰テスト
- 影響を追跡した箇所：
- 実行した回帰テスト：
- 未実施の回帰テストと理由：
- 変更しなかった箇所と理由：

## 6. 未解決事項・残存リスク
| 内容 | 分類 | 根拠 | 影響 | 次に必要な対応 |
|---|---|---|---|---|

## 7. 次工程への引き継ぎ
- 実装内容と変更ファイル：
- 実施済みテストと実結果：
- 01の計画との差異：
- 未実施テスト：
- 未解決事項：
- 03で重点確認すべきリスク：

## 8. 実装結果
- 実装完了
- 実装完了（テスト一部未実施）
- 実装中断
- 修正が必要

## 9. 共通の出力ルール
出力の見やすさ、作業状態の表記、根拠の示し方、テスト結果の表記は、`AI_CODING_RULES.md` 第41章「人が読みやすい出力・報告ルール」に従ってください。このプロンプト内の工程固有の報告項目は省略せず、共通ルールと矛盾しない形で維持してください。

実際のファイルと結果を根拠に報告し、未実施の確認を完了扱いにしないでください。
```
