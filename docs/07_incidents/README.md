# 障害管理

## 概要

本番・検証環境で発生した障害の記録・原因調査・修正・テストを管理するフォルダ。
障害1件につき1ディレクトリを作成し、関連ドキュメントを格納する。

---

## ディレクトリ命名規則

```
YYYYMMDD_[障害を表す短い名称（英字ケバブケース）]/
```

**例**
```
20260407_order-total-calculation-error/
20260408_login-session-timeout/
20260410_product-image-not-displayed/
```

- `YYYYMMDD`: 障害が検知された日付
- 名称は内容が一目でわかる簡潔な英語表記とする
- 複数単語はハイフン（`-`）でつなぐ

---

## 各ディレクトリの構成

| ファイル | 説明 | 作成タイミング |
|---|---|---|
| `01_incident-report.md` | 障害表（概要・発生状況・影響範囲・暫定対応） | 障害検知時 |
| `02_root-cause-analysis.md` | 原因調査（再現手順・根本原因・再発防止策） | 調査フェーズ |
| `03_fix-plan.md` | 修正計画（修正対象モジュール・変更内容・対応方針） | 修正フェーズ |
| `04_test-plan.md` | テスト計画・テストケース・実施結果 | テストフェーズ |

ひな型は [`_template/`](./_template/) を参照すること。

---

## ステータス管理

各 `01_incident-report.md` のヘッダに以下のステータスを記載する。

| ステータス | 意味 |
|---|---|
| `🔴 調査中` | 障害を検知し、原因調査中 |
| `🟡 修正中` | 根本原因が特定され、修正作業中 |
| `🔵 テスト中` | 修正完了、テスト実施中 |
| `✅ 完了` | テスト合格・リリース済み |
| `⏸ 保留` | 対応を保留（理由を記載） |

---

## ワークフロー

```
1. 🔴 調査中    障害検知 → 01_incident-report.md 起票 → 02_root-cause-analysis.md 調査開始
                成果物: 01_incident-report.md, 02_root-cause-analysis.md

2. 🟡 修正中    根本原因確定 → 03_fix-plan.md 作成 → 実装・修正
                成果物: 03_fix-plan.md

3. 🔵 テスト中   修正完了 → 04_test-plan.md 作成 → テスト実施
                成果物: 04_test-plan.md

4. ✅ 完了      テスト合格 → リリース → ステータス更新
```
