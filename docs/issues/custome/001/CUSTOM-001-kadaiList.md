### Q-01 　実装する優先コンテキストはどれですか？

- **ステータス**: 回答済み
- **背景**: 要件定義書では A（商品詳細）・B（カート）・C（トップ）の 3 箇所を提案しています。初回リリースに含めるものとフェーズ 2 以降に回すものを確認します。

| コンテキスト | 説明 | 初回実装 / 後回し |
|------------|------|----------------|
| A. 商品詳細「関連商品」 | `recommended_related_products` を即時活用できる | |
| B. カート「こちらもいかがですか？」 | 同上 | |
| C. トップ「あなたへのおすすめ」（会員限定） | パーソナライズロジックが必要 | |

**解答欄**:
```
トップ画面で最近見た商品の下に表示してください。
```

### Q-02　未ログインユーザーへのトップページ対応はどうしますか？

- **ステータス**: 回答済み
- **背景**: 要件定義書では C のセクションをログイン中会員のみ表示としています。未ログイン時に「売れ筋ランキング」で代替表示するか、セクション自体を非表示にするかを確認します。

| 選択肢 | 説明 |
|--------|------|
| 1. 非表示 | セクションを表示しない（現状の実装が最もシンプル） |
| 2. 売れ筋ランキングで代替 | `popular_product_rankings` の上位をそのまま表示 |
| 3. その他 | |

**解答欄**:
```
フェーズ1としては未ログインのユーザは対象外としてください。
フェーズ2にて未ログインユーザに売れ筋ランキングからお薦めする機能を追加することとします。
```

## セクション A — 商品詳細の関連商品

---

### Q-03　在庫切れ商品の表示可否はどうしますか？

- **ステータス**: 回答済み
- **背景**: 要件定義書では在庫切れでも表示とし、カード上で在庫状態を提示する方針を提案しています。ユーザー体験の観点から変更が必要な場合は指定してください。

| 選択肢 | 説明 |
|--------|------|
| 1. 表示する（提案通り） | 在庫切れバッジを表示 |
| 2. 表示しない | 推薦結果から除外し、件数が足りない場合は次の候補で補完 |

**解答欄**:
```
在庫切れでも表示してください。在庫切れの場合、お薦め表示時点で分かるように表示してください。
```

### Q-04　セクション A の表示件数は 4件で問題ありませんか？

- **ステータス**: 回答済み
- **背景**: `recommended_related_products` の `rank` は 1〜4 で設計されているため、最大 4件を提案しています。件数変更がある場合はバッチ側の再設計も必要になります。

**解答欄**:
```
最大4件で問題ありません。
```

### Q-05　カート内複数商品がある場合の基準商品の選択方法を確認します

- **ステータス**: 回答済み
- **背景**: 要件定義書では「カートに最初に入った商品」を基準としています。他の選択肢としては「直近に追加した商品」や「金額が最も高い商品」も考えられます。

| 選択肢 | 説明 |
|--------|------|
| 1. 最初に追加した商品（提案通り） |  |
| 2. 最後に追加した商品 |  |
| 3. 金額が最も高い商品 |  |
| 4. 全商品を起点に候補をマージして重複排除 |  |

**解答欄**:
```
お薦めはカートに入っている商品を元にせず、最近見た商品を踏まえた別商品の提案を行ってください。
```

### Q-06　カートセクションにカート追加ボタンを設けますか？

- **ステータス**: 回答済み
- **背景**: セクション B の商品カードにカート追加ボタン（またはリンク）を付けて直接追加できるようにするか、商品詳細へ誘導するだけにするかを確認します。

| 選択肢 | 説明 |
|--------|------|
| 1. カート追加ボタンあり | 商品詳細を経由せず即時追加できる（バリアント選択が必要な場合は詳細ページへ） |
| 2. 詳細ページへのリンクのみ | 既存の商品カードと同じ動線 |

**解答欄**:
```
フェーズ1では商品詳細へ誘導するだけとします。
フェース2にて直接追加できるようにすることとしてください。
```

## セクション C — トップページのパーソナライズ

---

### Q-07　購入履歴の参照期間は「直近3ヶ月」で問題ありませんか？

- **ステータス**: 回答済み
- **背景**: オフィス家具は購入頻度が低い商品のため、3ヶ月よりも長い期間（例：6ヶ月・12ヶ月）の方が推薦候補が得られやすい可能性があります。

**解答欄**:
```
直近6カ月とします。
```

---

### Q-08　「あなたへのおすすめ」のパーソナライズ対象は購入履歴のみですか？

- **ステータス**: 回答済み
- **背景**: 現在、ブラウザ Cookie に「最近見た商品（`recently-viewed`）」が保存されています（`/products/recently-viewed` API）。これを購入履歴と組み合わせてパーソナライズに使うことも可能です。

| 選択肢 | 説明 |
|--------|------|
| 1. 購入履歴 + お気に入りのみ（提案通り） |  |
| 2. 購入履歴 + お気に入り + 最近見た商品 | Cookie の閲覧履歴も加味する |

**解答欄**:
```
最近見た商品と購入履歴を組み合わせてください。
```

---

### Q-09　購入済み商品を推薦から除外するルールを確認します

- **ステータス**: 回答済み
- **背景**: 要件定義書では「購入済み商品（全期間）を除外」と提案しています。オフィス家具の場合、同じ商品を複数回購入するケース（買い増し、追加購入）も考えられます。

| 選択肢 | 説明 |
|--------|------|
| 1. 全期間で除外（提案通り） |  |
| 2. 直近3ヶ月のみ除外 | 古い購入品は再推薦する |
| 3. 除外しない | 買い増し需要を重視 |

**解答欄**:
```
2. 直近3ヶ月のみ除外としてください
```

## バッチ・インフラ

---

### Q-10　`recommended_related_products` の推薦アルゴリズムは変更しますか？

- **ステータス**: 回答済み
- **背景**: 現在のバッチ（`recommended-related` ジョブ）が生成する類似度スコアの算出ロジックは本要件定義の対象外としています。ただし、将来的にアルゴリズムを変更する可能性がある場合は影響を把握しておく必要があります。

**解答欄**:
```
変更しません
```

---

### Q-11　推薦データが当日まだ生成されていない場合（バッチ未実行）の挙動はどうしますか？

- **ステータス**: 回答済み
- **背景**: バッチが毎日実行されますが、実行前の時間帯や障害時は最新の `recommendation_date` が前日以前のデータになります。

| 選択肢 | 説明 |
|--------|------|
| 1. 利用可能な最新日付のデータをそのまま使う（提案通り） | 多少古くても推薦を表示する |
| 2. 一定日数以上古い場合は非表示 | 例：2日以上前のデータは使わない |

**解答欄**:
```
1. 利用可能な最新日付のデータをそのまま使うとしてください
```
