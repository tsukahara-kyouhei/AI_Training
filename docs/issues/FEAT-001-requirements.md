# FEAT-001 商品検索機能強化 要件定義書

| 項目 | 内容 |
|------|------|
| 機能ID | FEAT-001 |
| 機能名 | 商品検索機能強化 |
| 作成日 | 2026-03-16 |
| ステータス | 要件定義確定 |

---

## 1. 目的

商品検索のヒット率を上げ、離脱率を下げることを目的として、商品検索機能を強化する。

---

## 2. 対象範囲

| 対象 | 説明 |
|------|------|
| ヘッダ検索ボックス | 全ページ共通ヘッダに配置されたキーワード入力フォーム |
| 検索結果一覧ページ | `/products/search` エンドポイントが返す一覧画面 (`product-list-search-results.html`) |

上記以外（カテゴリ一覧、商品詳細、カート等）は対象外。

---

## 3. 機能要件

### 3.1 商品コード検索

- 商品コード（`product_variants.product_code`）の検索マッチは **完全一致を優先し、完全一致でヒットがない場合のみ前方一致** で再検索する（フォールバック方式）。
- 中間一致は不可とする（意図しない部分マッチを防止するため）。
- 完全一致でヒットした場合は前方一致での追加検索は行わない。

### 3.2 テキストフィールド部分一致検索

以下のフィールドは **部分一致（LIKE）検索** をサポートする。

| フィールド | テーブル / カラム |
|-----------|-----------------|
| 商品名 | `products.product_name` |
| シリーズバリエーション名 | `products.variation_name` |
| 説明文 | `products.description` |

### 3.3 大文字・小文字の区別

- 英字の検索は **大文字・小文字を区別しない**（例：`DESK` で `desk` / `Desk` がヒットする）。

### 3.4 全角・半角の正規化

- **数字・英字・カタカナ** について、全角・半角を区別せずに検索できること。
  - 例：`ｱｲｳ` と `アイウ` は同一視される
  - 例：`ＡＢＣ` と `ABC` は同一視される
  - 例：`１２３` と `123` は同一視される
- ひらがな・漢字・記号は本要件の正規化対象外とする。
- 正規化はアプリケーション層（Java）で実装する。入力キーワードを半角・小文字に変換してからSQLへ渡す。DB側には変換処理を持たない。

### 3.5 テイスト絞り込み条件の追加

- 検索結果画面の絞り込みサイドバー（およびモバイル用モーダル）に **「テイスト」チェックリスト** を追加する。
- UI仕様・操作仕様は各カテゴリ一覧ページ（デスク一覧 / チェア一覧 / 収納家具一覧）に実装済みのテイスト絞り込みと同一とする。
  - チェックボックスの複数選択が可能。
  - 「絞り込む」ボタン押下で検索が実行される。
  - 絞り込みリセット時はテイスト選択もクリアされる。
- **選択肢の取得**：`desk_tastes` / `chair_tastes` / `storage_tastes` の3テーブルを `display_name` で UNION し、重複を除いたテイスト名称一覧を選択肢として表示する。
- **絞り込みの適用**：選択されたテイスト名称に対して、各カテゴリの属性テーブル（`product_desk_attributes` / `product_chair_attributes` / `product_storage_attributes`）を OR 条件で横断検索する。

### 3.6 その他（現行踏襲）

以下の仕様は現行の商品検索機能をそのまま踏襲する。

- 在庫有のみ表示フィルタ
- 価格帯フィルタ
- カラーフィルタ
- 並び順（おすすめ順 / 新しい順 / 価格が安い順 / 価格が高い順）
- 表示件数（15 / 30 / 60件）
- ページネーション
- ページ超過時の最終ページへの補正

---

## 4. 性能要件

| 指標 | 目標値 |
|------|--------|
| 検索対象商品の最大件数 | 1,000件程度 |
| 検索結果一覧の初回表示 | **本番環境でのサーバーサイド応答時間（TTFB）が、実測値の95パーセンタイルで2秒以内** |
| テイスト絞り込みあり検索の割合 | 全検索リクエストの約5%と想定し、性能目標の負荷条件に含める |

---

## 5. 非機能要件

### 5.1 セキュリティ

- キーワード・絞り込みパラメータはすべて検索 SQL の外部入力値として扱い、SQL インジェクション対策（パラメータバインド）を維持する。
- 正規化処理（全角・半角変換）はアプリケーション層（Java）で実装し、変換後の値をバインドパラメータとしてSQLへ渡す。入力値を直接SQLへ埋め込むことは行わない。

### 5.2 後方互換性

- 既存の URL パラメータ（`q`, `inStockOnly`, `priceBand`, `color`, `sort`, `page`, `size`）は変更しない。
- テイスト絞り込みのリクエストパラメータ名は新規追加とする（既存パラメータとの衝突なし）。
