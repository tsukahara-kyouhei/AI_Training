# FEAT-001 商品検索機能強化 要件定義書

## 1. 背景・目的

商品検索のヒット率を上げ、離脱率を下げるために商品検索機能を強化する。

具体的には下記の課題に対応する。

- 現状の検索対象が商品名・商品コードのみであり、説明文やバリエーション名がヒットしない
- 商品コードが部分一致のため、意図しない商品がヒットする
- 全角・半角の違いにより検索漏れが発生している
- 検索結果画面にテイスト絞り込みがなく、カテゴリ一覧画面と機能が乖離している

---

## 2. 対象範囲

| 対象 | 説明 |
|------|------|
| ヘッダの検索ボックス | キーワードの入力・送信 |
| 検索結果一覧画面 | 検索結果の表示・絞り込み |

管理画面・受注後処理・カテゴリ一覧画面（デスク・チェア・収納）は対象外。

---

## 3. 現状の仕様

### 3.1 検索対象フィールド

| フィールド | テーブル.カラム | 現状 |
|------------|----------------|------|
| 商品名 | `products.product_name` | 部分一致（`ILIKE`）対象 |
| 商品コード | `product_variants.product_code` | 部分一致（`ILIKE`）対象 |
| バリエーション名 | `products.variation_name` | **検索対象外** |
| 商品紹介文 | `products.description` | **検索対象外** |

### 3.2 絞り込み条件

検索結果一覧では、現状以下の絞り込みが可能。

- 在庫あり
- カラー
- 価格帯

テイスト絞り込みは**未実装**。カテゴリ一覧画面にはテイスト絞り込みが実装済み。

### 3.3 文字の正規化

- 大文字・小文字の区別なし：PostgreSQL の `ILIKE` により対応済み
- 全角・半角の区別なし：**未対応**

---

## 4. 機能要件

### 4.1 商品コード検索（変更）

**仕様変更：部分一致 → 完全一致または前方一致**

| 条件 | 適用 |
|------|------|
| 完全一致 | 適用 |
| 前方一致 | 適用 |
| 中間一致 | **不適用** |
| 後方一致 | **不適用** |

**変更理由：** 中間一致では商品コードの一部の数字が意図せずマッチしてしまうため。

**対象カラム：** `product_variants.product_code`（`VARCHAR(32)`）

**検索ロジック：** 入力キーワードを正規化した後、以下いずれかと一致する商品コードを持つバリアントを含む商品をヒットとする。

```
product_code = :keyword          -- 完全一致
OR product_code ILIKE :keyword%  -- 前方一致
```

### 4.2 検索対象フィールドの拡張（追加）

**仕様追加：バリエーション名・商品紹介文を部分一致検索対象に追加**

変更後の検索対象は以下のとおり。

| フィールド | テーブル.カラム | 一致方法 |
|------------|----------------|---------|
| 商品名 | `products.product_name` | 部分一致 |
| バリエーション名 | `products.variation_name` | 部分一致 |
| 商品紹介文 | `products.description` | 部分一致 |
| 商品コード | `product_variants.product_code` | 完全一致または前方一致（4.1参照） |

複数フィールドは **OR 条件** で結合し、いずれかにマッチすれば検索結果に含める。

> **`variation_name` が NULL の商品（バリエーションなし商品）はバリエーション名検索の対象外とする。** `product_name` や `description` にマッチした場合は検索結果に含まれる。

### 4.3 大文字・小文字の区別なし（現状維持）

英字については大文字・小文字を区別しない。PostgreSQL の `ILIKE` で対応済みのため、引き続き同仕様を維持する。

### 4.4 全角・半角の正規化（追加）

数字・英字・カタカナについて、全角・半角を区別せずに検索できること。

**正規化の方向：** 入力キーワードおよびDB格納データを**全角へ統一**して比較を行う。

| 対象文字種 | 正規化例 |
|----------|---------|
| 数字 | `123` → `１２３` |
| 英字 | `Abc` → `Ａｂｃ` |
| カタカナ | `ﾃﾞｽｸ` → `デスク` |

**正規化の実施タイミング：** 検索クエリ発行前にアプリケーション層（Java）で正規化処理を行う。DBには正規化済みのキーワードを渡す。

> **実装上の注意：** DB側の格納データも同一基準（全角）に変換してから比較する必要がある。SQL上でカラム値を変換する関数を用いるか、アプリ側の変換関数を利用するかは実装フェーズで決定する（未決事項 #1 参照）。

### 4.5 テイスト絞り込みの追加（追加）

検索結果一覧の絞り込み条件に「テイスト」を追加する。

#### 4.5.1 機能概要

カテゴリ一覧画面のテイスト絞り込み（デスク・チェア・収納それぞれの実装）と同仕様とする。

- テイスト選択肢はチェックボックス形式で複数選択可能
- 未選択時は絞り込みを行わない
- 選択状態は再検索・ページ遷移後も保持される（クエリパラメータで管理）

#### 4.5.2 データ構造とテイストマスタ

現在、テイストマスタはカテゴリ別に3テーブルで管理されている。

| カテゴリ | マスタテーブル | 属性テーブル（taste_id カラム） |
|----------|--------------|-------------------------------|
| デスク | `desk_tastes` | `product_desk_attributes.taste_id` |
| チェア | `chair_tastes` | `product_chair_attributes.taste_id` |
| 収納 | `storage_tastes` | `product_storage_attributes.taste_id` |

#### 4.5.3 検索結果画面におけるテイスト絞り込みの仕様

検索結果はカテゴリをまたいで表示されるため、テイスト絞り込みはカテゴリごとに独立して適用する。

- テイスト選択肢は3カテゴリのマスタを**名称統合**して一覧表示する（カテゴリ別のグルーピングは行わない）
- 各カテゴリのテイストは当該カテゴリのマスタから有効（`is_active = TRUE`）なものを `sort_order` 順に取得し、重複する名称はひとつにまとめる
- 絞り込み条件の適用は、各カテゴリ属性テーブルへの `taste_id IN (...)` でフィルタリングする

#### 4.5.4 カテゴリ一覧画面との差異

| 項目 | カテゴリ一覧 | 検索結果一覧（本機能） |
|------|------------|----------------------|
| 対象カテゴリ | 単一 | 複数（デスク・チェア・収納） |
| テイスト選択肢 | 単一カテゴリのマスタ | 複数カテゴリのマスタを名称統合して表示 |
| 絞り込みSQL | 単一属性テーブルにEXISTS | 複数属性テーブルにEXISTSを組み合わせ |

### 4.6 その他の検索・絞り込み条件（現状維持）

以下の条件は現状の仕様を踏襲し、変更しない。

- 在庫あり絞り込み
- カラー絞り込み
- 価格帯絞り込み
- 並び順（並び替え）
- ページネーション
- 販売中商品のみ対象（`sale_start_at` / `sale_end_at` によるフィルタ）

## 7. 前提・制約

- 商品コードは `product_variants.product_code`（`VARCHAR(32)`）で管理されており、商品単体ではなくバリアント単位で付与される
- テイストマスタはカテゴリ別テーブル（`desk_tastes` / `chair_tastes` / `storage_tastes`）で管理されており、テーブル統合は本機能のスコープ外
- 全角・半角の正規化はアプリケーション層（Java）で実装し、DBスキーマ変更は行わない
- 性能目標はローカル環境ではなく本番相当環境（またはステージング環境）を基準とする
